# Task pack: Delete a todo

## Goal
Let users delete a todo, in both the logic (`src/todo.js`) and the web page, so that `acceptance/features/delete.feature` passes:
- Deleting an existing todo removes it and leaves the others in their original order.
- Deleting a todo that does not exist throws an `Error` with the message `Todo not found`.

All existing unit and acceptance tests must keep passing.

## Plan
1. **Check that the test fails first.** Run `npm run acceptance` and confirm that `delete.feature` fails because its steps are undefined.
2. **Add `remove(id)` to `TodoList`** in `src/todo.js`:
   - Find the todo by `id`. If none matches, `throw new Error('Todo not found')`.
   - Otherwise remove it from `#todos` and return a copy of it (`{ ...todo }`).
   - Do not change `add`, `items` or `size`. Keep DOM code out of this file.
   - Delete by `id`, not by text, because two todos can share the same text.
3. **Add unit tests** to `test/todo.test.js`:
   - `remove` deletes the right todo and keeps the order of the rest.
   - `remove` returns the deleted todo.
   - `remove` with an unknown id throws `Todo not found` and leaves the list unchanged.
   - `remove` on an empty list throws `Todo not found`.
   - Two todos with the same text: removing one by id leaves the other.
   - Removing the same id twice throws on the second call.
   - `size` goes down after a remove.
4. **Add step definitions** in a new file, `acceptance/steps/delete.steps.js`:
   - `Given a todo list with {string} and {string}`: create a new `TodoList`, add both texts, and set `this.error = null`.
   - `When I delete {string}`: find the todo with that text in `this.list.items()` and call `this.list.remove(todo.id)`. If no todo has that text, still call `remove` with an id that doesn't exist (for example `undefined`) so the error comes from the logic. Catch any error into `this.error`.
   - Reuse the existing steps `an empty todo list`, `the list contains only {string}` and `I see the error {string}` from `basics.steps.js`. Do not define them again, because Cucumber fails on duplicate step definitions.
5. **Update the web page:**
   - `web/app.js`: in `render()`, give each `<li>` a text span and a "Delete" button. The button needs an `aria-label` that names the todo, such as `Delete "Buy milk"`. On click, call `list.remove(todo.id)`, clear `#error` and call `render()`. On failure, show `err.message` in `#error`.
   - `web/index.html`: add only the CSS needed so the row is a flex layout with the text on the left and a small delete button on the right. Use the existing CSS variables, and keep it readable in dark mode.
6. **Run all checks:** `npm test`, `npm run acceptance` and `npm run guard`. All three must pass.
7. **Smoke test the page:** run `npm run build`, then `npm run serve`. Add two todos, delete one, and check that the "Nothing to do yet." message shows again once the list is empty.
8. **Commit in small steps** with conventional messages, for example:
   - `feat: add TodoList.remove`
   - `test: unit tests for remove`
   - `test: step definitions for delete feature`
   - `feat: delete button on web page`
