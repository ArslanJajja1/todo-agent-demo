# Task pack: no-duplicates

## Goal
Stop the todo list from holding the same task twice, in both the logic (`src/todo.js`) and the web page, so that `acceptance/features/no-duplicates.feature` passes:
- Adding a todo whose text matches an existing todo throws an `Error` with the message `Todo already exists`, and the list stays unchanged.
- The match ignores surrounding whitespace, internal spacing and letter case. For example, `"  buy MILK "` is a duplicate of `"Buy milk"`.
- Renaming a todo to text that matches a different todo is rejected the same way, so duplicates can't get in through rename. Renaming a todo to its own text with different capitals (for example, `"Buy milk"` to `"Buy Milk"`) is still allowed.

All existing unit tests and acceptance tests (`basics.feature`, `count.feature`, `delete.feature`, `rename.feature`) must keep passing.

## Plan
1. **Check that the test fails first.** Run `npm run acceptance`. Both `no-duplicates.feature` scenarios should fail at `Then I see the error "Todo already exists"` with "Expected an error but none was thrown". All steps already exist in `acceptance/steps/basics.steps.js`, so you don't need new step definitions. If any step shows as undefined, stop and report it.
2. **Add a private normalize helper** in `src/todo.js`, for example `#key(text)`. It trims, collapses runs of whitespace to one space and lowercases, so it returns `String(text).trim().replace(/\s+/g, ' ').toLowerCase()`. Use it only for comparing. The stored `text` is still just trimmed, which is how `add` and `rename` work now.
3. **Reject duplicates in `add(text)`.** After the existing empty-text check, if any todo's key equals the new key, `throw new Error('Todo already exists')`. Do this before `#nextId++` so a rejected add doesn't use up an id.
4. **Reject duplicates in `rename(id, text)`.** Keep the current order of checks: empty text, then `Todo not found`. Then, if another todo (`t.id !== id`) has the same key, `throw new Error('Todo already exists')`. On any error, nothing changes.
5. **Update unit tests in `test/todo.test.js`:**
   - Two existing tests add `"Buy milk"` twice and will break: `remove by id leaves another todo with the same text` (around line 84) and `rename by id leaves another todo with the same text` (around line 149). Change them to use two different texts and keep what they check: removing or renaming by id only affects that one todo. Don't delete them. These are unit tests, not the customer's contract, so you may change them.
   - Add these tests:
     - Adding the exact same text twice throws `Todo already exists`, and `size` stays at 1.
     - Adding `"  buy MILK "` after `"Buy milk"` throws, and so does `"Buy   milk"`.
     - A failed duplicate add leaves `items()` unchanged and doesn't use up an id, so the next good add gets the next id.
     - Adding the text of a todo that was removed works.
     - Different texts such as `"Buy milk"` and `"Buy milks"` are both accepted.
     - Renaming to another todo's text, in any case or spacing, throws `Todo already exists` and leaves the list unchanged.
     - Renaming a todo to its own text with different capitals works.
6. **Check the web page.** `web/app.js` already shows `err.message` in `#error` for both add and rename, and keeps the input text when an error happens. So you should not need to change any code. Only edit `web/app.js` if the smoke test in step 8 shows a gap, and keep that change small.
7. **Run all checks:** `npm test`, `npm run acceptance` and `npm run guard`. All three must pass.
8. **Smoke test the page:** run `npm run build`, then `npm run serve`. Add `Buy milk`, then add `  buy MILK `. Check that `Todo already exists` shows, the count still says `1 todo`, and the typed text stays in the input. Then add `Call mom` and try to rename it to `BUY MILK`. Check that the error shows and the rename input stays open. Finally, check that adding a new todo clears the error.
9. **Commit in small steps** with conventional messages, for example:
   - `test: unit tests for duplicate todos`
   - `feat: reject duplicate todos on add`
   - `feat: reject duplicate todos on rename`
