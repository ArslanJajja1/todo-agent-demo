# Task pack: Rename a todo

## Goal
Let users rename a todo, in both the logic (`src/todo.js`) and the web page, so that `acceptance/features/rename.feature` passes:
- Renaming an existing todo changes its text and leaves the other todos unchanged and in their original order.
- Renaming a todo to empty text throws an `Error` with the message `Todo text cannot be empty`, and the list stays unchanged.

All existing unit and acceptance tests (`basics.feature`, `delete.feature`) must keep passing.

## Plan
1. **Check that the test fails first.** Run `npm run acceptance` and confirm that `rename.feature` fails because its steps `I rename {string} to {string}` and `the list contains {string} and {string}` are undefined.
2. **Add `rename(id, text)` to `TodoList`** in `src/todo.js`:
   - Trim the new text the same way `add` does (`String(text ?? '').trim()`). If the result is empty, `throw new Error('Todo text cannot be empty')`.
   - Find the todo by `id`. If none matches, `throw new Error('Todo not found')`.
   - Check the text before looking up the id, so a bad call never changes anything.
   - Update only `text`. Keep the same `id`, `done` value and position in the list.
   - Return a copy of the updated todo (`{ ...todo }`).
   - Do not change `add`, `remove`, `items` or `size`. Keep DOM code out of this file.
   - Rename by `id`, not by text, because two todos can share the same text.
3. **Add unit tests** to `test/todo.test.js`:
   - `rename` changes the text and returns the updated todo.
   - `rename` keeps the `id`, the `done` value and the order of the list.
   - `rename` trims the new text.
   - `rename` to `''` or to whitespace only throws `Todo text cannot be empty` and leaves the list unchanged.
   - `rename` with an unknown id throws `Todo not found` and leaves the list unchanged.
   - Two todos with the same text: renaming one by id leaves the other.
   - `size` does not change after a rename.
4. **Add step definitions** in a new file, `acceptance/steps/rename.steps.js`:
   - `When I rename {string} to {string}`: find the todo with the first text in `this.list.items()` and call `this.list.rename(todo?.id, newText)`. Catch any error into `this.error`.
   - `Then the list contains {string} and {string}`: assert that the texts from `this.list.items()` deep-equal `[first, second]`, in that order.
   - Reuse `a todo list with {string} and {string}` from `delete.steps.js` and `I see the error {string}` from `basics.steps.js`. Do not define them again, because Cucumber fails on duplicate step definitions.
5. **Update the web page:**
   - `web/app.js`: in `render()`, add a "Rename" button next to the Delete button, with an `aria-label` that names the todo, such as `Rename "Buy milk"`. On click, swap the text span for an `<input>` filled with the current text and focus it. Enter (or blur) calls `list.rename(todo.id, input.value)`, clears `#error` and calls `render()`. Escape cancels and calls `render()`. On failure, show `err.message` in `#error` and keep the input open so the user can fix it.
   - `web/index.html`: add only the CSS needed for the Rename button and the inline edit input. Reuse the existing `button.delete` look and CSS variables, and keep it readable in dark mode.
6. **Run all checks:** `npm test`, `npm run acceptance` and `npm run guard`. All three must pass.
7. **Smoke test the page:** run `npm run build`, then `npm run serve`. Add two todos, rename one and check the new text shows in the same place. Try renaming to empty text and check that `Todo text cannot be empty` shows and the old text is kept. Check that Escape cancels and that Delete still works.
8. **Commit in small steps** with conventional messages, for example:
   - `feat: add TodoList.rename`
   - `test: unit tests for rename`
   - `test: step definitions for rename feature`
   - `feat: rename todos on web page`
