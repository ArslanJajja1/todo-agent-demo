# Task pack: count

## Goal
Show how many todos are in the list, both in the logic (`src/todo.js`) and on the web page, so that `acceptance/features/count.feature` passes:
- A list with "Buy milk" and "Call mom" shows `2 todos`.

The count includes every todo, done or not. The label uses the right plural: `0 todos`, `1 todo`, `2 todos`. All existing unit and acceptance tests (`basics.feature`, `delete.feature`, `rename.feature`) must keep passing.

## Plan
1. **Check that the test fails first.** Run `npm run acceptance` and confirm that `count.feature` fails only because the step `I see {string}` is undefined. The step `a todo list with {string} and {string}` already exists in `delete.steps.js`.
2. **Add `countLabel()` to `TodoList`** in `src/todo.js`:
   - Return `` `${this.size} todo` `` when `size` is 1, and `` `${this.size} todos` `` for any other number, including 0.
   - Build it from the existing `size` getter. Do not add any new state.
   - Do not change `add`, `remove`, `rename`, `items` or `size`. Keep DOM code out of this file.
   - Keep the label text in `src/todo.js` so the web page and the acceptance step use the same wording.
3. **Add unit tests** to `test/todo.test.js`:
   - An empty list gives `0 todos`.
   - One todo gives `1 todo`.
   - Two todos give `2 todos`.
   - The label updates after `add` and after `remove`.
   - A failed `add('')` does not change the label.
   - A done todo still counts. Only add this test if there is already a public way to mark a todo done. Do not add one for this task.
4. **Add step definitions** in a new file, `acceptance/steps/count.steps.js`:
   - `Then I see {string}`: assert that `this.list.countLabel()` equals the expected text.
   - Reuse `a todo list with {string} and {string}` from `delete.steps.js`. Do not define it again, because Cucumber fails on duplicate step definitions.
   - Make sure `I see {string}` does not clash with `I see the error {string}` in `basics.steps.js`. Run the whole acceptance suite and confirm there are no "ambiguous step" errors.
5. **Update the web page:**
   - `web/index.html`: add one element for the count, `<p id="count" class="count" aria-live="polite"></p>`, between the list and the empty message. Add only the CSS it needs, using the existing CSS variables (for example, `color: var(--muted)` and a small font size) so it stays readable in dark mode.
   - `web/app.js`: get `#count` once. At the end of `render()`, set its `textContent` to `list.countLabel()`. Because add, delete and rename already call `render()`, the count stays up to date.
6. **Run all checks:** `npm test`, `npm run acceptance` and `npm run guard`. All three must pass.
7. **Smoke test the page:** run `npm run build`, then `npm run serve`. Check that the page shows `0 todos` at the start, `1 todo` after one add, and `2 todos` after a second add. Delete one and check that it goes back to `1 todo`. Check that renaming does not change the count, and that an empty add shows the error and leaves the count as it was.
8. **Commit in small steps** with conventional messages, for example:
   - `feat: add TodoList.countLabel`
   - `test: unit tests for count label`
   - `test: step definitions for count feature`
   - `feat: show todo count on web page`
